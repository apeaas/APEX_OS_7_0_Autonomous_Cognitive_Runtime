APEX 7.1 — CONSTITUTIONAL COGNITIVE VOICE RUNTIME
GUÍA DE INSTALACIÓN Y OPERACIÓN

============================================================
1. ALCANCE
============================================================

APEX 7.1 es un runtime local para observación, investigación, simulación,
explicación, conversación y decisión patrimonial PAPER.

Incluye:
- sesión local criptográfica y guards uniformes;
- lifecycle de acciones con claims ligados a sesión;
- portfolio PAPER canónico en backend;
- ledger append-only e idempotente;
- Safety Kernel y Constitución Patrimonial versionada;
- Unified Risk y Governance determinísticos;
- Fondo Autónomo PAPER con aporte inicial fijo máximo de 5%;
- ImprovementProposal y Decision Journal auditables;
- consola Realtime Voice/WebRTC con fallback mock/texto.

No incluye Quantum Surfer, brokers, exchanges autenticados, wallets, firmas,
custodia, depósitos, retiros, transferencias ni dinero real.

============================================================
2. REQUISITOS E INICIO
============================================================

- Node.js mínimo: 18.0.0.
- Validación realizada en Windows 10.0.19045 x64 y Node v24.18.0.
- Windows: start_apex.bat
- macOS/Linux: ./start_apex.sh
- URL: http://127.0.0.1:5500

No abras index.html con doble clic: el backend es obligatorio para la sesión,
el ledger, Risk, Governance y voz.

En el primer arranque se crea .env desde .env.example. Sin OPENAI_API_KEY la
aplicación carga y la voz usa el mock determinístico claramente identificado.

============================================================
3. CONFIGURACIÓN
============================================================

Variables principales:

OPENAI_API_KEY=
OPENAI_MODEL=gpt-5.1
OPENAI_REALTIME_MODEL=gpt-realtime
APEX_HOST=127.0.0.1
APEX_PORT=5500
APEX_AI_RATE_LIMIT=60

Límites de voz:

APEX_VOICE_SESSION_TTL_MS=900000
APEX_VOICE_CONNECT_TIMEOUT_MS=20000
APEX_VOICE_MAX_RECONNECTS=3
APEX_VOICE_MAX_TOOL_CALLS=40
APEX_VOICE_MAX_RESPONSES=48

Si se publica detrás de una interfaz distinta, configurá explícitamente
APEX_ALLOWED_HOSTS y APEX_ALLOWED_ORIGINS. La clave OpenAI vive únicamente en
backend y nunca debe copiarse a index.html, assets/js, logs o capturas.

============================================================
4. JERARQUÍA Y MODOS
============================================================

Autoridad:

Safety Kernel
→ Constitución Patrimonial
→ Governance
→ Unified Risk
→ confirmación humana cuando corresponda
→ ledger PAPER

Modos:
- OBSERVE: lectura e investigación.
- COPILOT: preparación de planes, casos y CommandDraft.
- PAPER AUTONOMOUS: acciones PAPER con claim, Risk, Governance y Fondo activo.
- SUSPENDED: kill switch o pausa; no admite nuevas mutaciones.

Frases:
- activar PAPER autónomo: HABILITAR PAPER AUTO
- reanudar tras emergencia: REANUDAR APEX

El kill switch tiene prioridad absoluta. Ningún modelo o comando de voz puede
desactivarlo, elevar Risk, cambiar la Constitución o activar live.

============================================================
5. PORTFOLIO Y MIGRACIÓN
============================================================

El backend es la única autoridad de cash, equity, PnL y posiciones. El browser
sólo proyecta y envía comandos.

Al detectar `apex-portfolio` heredado en localStorage:
1. APEX muestra el contenido a migrar.
2. El operador confirma.
3. El backend valida todo el portfolio y calcula un fingerprint.
4. Se registra un único evento `legacy_portfolio_imported`.
5. El browser conserva un backup `operational:false`.
6. La clave operativa anterior se elimina y no vuelve a leerse como autoridad.

No edites archivos NDJSON mientras APEX está abierto. No borres eventos para
corregir una operación: usá comandos compensatorios o restaurá un backup en un
directorio separado.

============================================================
6. CONSOLA DE VOZ
============================================================

La consola persistente aparece en Mission Control y ofrece conectar,
desconectar, mute, interrupción, transcript y entrada de texto en la misma
sesión.

Con clave y acceso de cuenta:
- el browser solicita micrófono;
- WebRTC transporta audio;
- el backend autentica la llamada Realtime;
- la API key no llega al browser.

Sin clave, permiso, dispositivo o conectividad:
- el fallback usa mock/texto;
- el mock se rotula “MOCK · sin audio real”;
- nunca se simula una conexión de voz real.

Una solicitud mutable por voz recorre:

transcript → CommandDraft → confirmación visual ligada a sesión
→ API normal → Risk → Governance → efecto PAPER

“Interrumpir” cancela respuesta y limpia audio en curso. Audio crudo no se
almacena por defecto.

============================================================

Backup:
- Windows: backup_apex.bat
- Terminal: npm.cmd run backup

El backup incluye data/, config/, .env y VERSION.txt. Guardalo fuera del
directorio de trabajo antes de migrar o revertir código.

============================================================
9. SOLUCIÓN DE PROBLEMAS
============================================================

Puerto ocupado:
- cerrá otra instancia de APEX o cambiá APEX_PORT.

IA online ausente:
- revisá OPENAI_API_KEY;
- reiniciá el backend;
- consultá /api/health.

Micrófono denegado:
- habilitá Micrófono desde el candado del navegador;
- reconectá;
- continuá por mock/texto si no querés conceder permiso.

Feed degradado:
- investigación sigue permitida;
- toda conclusión market-dependent queda operable=false;
- no fuerces trusted desde UI, prompt o modelo.

Ledger no inicia:
- no lo edites;
- conservá el archivo y sus backups;
- ejecutá npm.cmd test;
- seguí docs/APEX_7_1_ROLLBACK.md.
